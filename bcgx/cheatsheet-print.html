CLT, standard error, interval

# Known sigma, independent rows: mean ± z * sigma/sqrt(n).
# z = norm.ppf(0.975) is the two-sided 95% point.
# Standardize a point as z = (x - mu) / sigma.
from scipy import stats
mean, sigma, n = 250.0, 15.0, 36
se = sigma / np.sqrt(n)
z = stats.norm.ppf(0.975)
(mean - z * se, mean + z * se)

t interval, sigma unknown

# Unknown sigma: mean ± t * s/sqrt(n), df = n - 1. s is the sample std.
from scipy import stats
s = pd.Series([248.0, 251, 249, 253, 250, 247])

tcrit = stats.t.ppf(0.975, len(s) - 1)
(s.mean() - tcrit * se, s.mean() + tcrit * se)

Tails, combinations, PPV

# P(A|positive) from prevalence, sensitivity and specificity.
# C(n,k) combinations. P(n,k) = n!/(n-k)! permutations.
# P(X >= k) = sf(k - 1) = 1 - cdf(k - 1).
from math import comb, factorial
p, sens, spec = 0.02, 0.90, 0.95
ppv = sens * p / (sens * p + (1 - spec) * (1 - p))

from scipy.stats import binom

# p is the chance of a result at least this extreme if H0

# The two-proportion z uses a normal approximation: enough

Correlation and causation

Correlation is a symmetric association. It does not pick a direction. A cause needs a reason: randomisation, a discontinuity, or an assumption you can defend. Conditioning on a mediator (a variable on the path from the cause to the effect) removes part of the effect you wanted. Conditioning on a common effect can create a fake association. A control that is only a common cause is the one you want.

ML theory

Bias and variance

High bias: train and test are both weak. The model is too rigid for the pattern. High variance: train is strong and test is weak. The model memorised the sample. More data mainly cuts variance. A richer model cuts bias. Regularisation, fewer features, and a shallower tree cut variance.

L1 and L2

L2 usually shrinks coefficients without making them exactly zero; correlated features can share weight. L1 can set coefficients exactly to zero and may select among correlated features. Penalties act on coefficient magnitudes. Rescaling a feature changes the coefficient required for the same predictions: larger-valued features need smaller coefficients and can be penalized less. Standardize predictors before comparing or regularizing coefficients.

Which metric

For equal per-row misclassification costs, accuracy summarizes the relevant error rate. F1 emphasizes the positive class and ignores true negatives; choose it when that tradeoff matches the objective, not simply because classes are balanced. Rare positives and a review budget: precision at the top k, or recall at a fixed precision. Accuracy hides a majority classifier. A ranking score: ROC-AUC, or PR-AUC when positives are rare. Gini = 2*ROC-AUC - 1 is ranking Gini, not a tree's impurity. Regression: MAE when outliers should not dominate, RMSE when large misses are expensive, R² against predicting the mean. MAPE explodes when an actual is 0. WAPE = sum(|error|) / sum(|actual|) needs a positive denominator.

Precision and recall

Precision = TP / (TP + FP): of the rows you flagged, how many were real. Recall = TP / (TP + FN): of the real positives, how many you flagged. Raising the threshold usually lifts precision and cuts recall. F1 = 2PR / (P + R). class_weight='balanced', or a threshold that is not 0.5, when the rare class is the one that matters. Pick the threshold on validation data and the business cost, not on the test set.

ROC and PR

ROC plots TPR against FPR = FP / (FP + TN). ROC-AUC measures ranking and is not itself driven by class prevalence when the class-conditional score distributions are unchanged. At low prevalence, even a small FPR can create many false alarms. Precision-recall and the workload at the chosen threshold are then informative. PR depends on prevalence. Select thresholds using validation data and business costs, not the test set.

Logistic coefficients

Logistic log-odds = intercept + Xβ. Increasing x_j by 1 multiplies the odds by exp(β_j), with the other predictors held fixed. The coefficient is not a probability and not a risk difference. Binary log-loss = −mean[y log(p) + (1 − y) log(1 − p)]. Use clipped probabilities, or sklearn.metrics.log_loss.

k-NN

Prediction is a vote or average of the k nearest training rows. Distance uses the feature scales, so standardize first. Smaller k tends toward lower bias and higher variance. Larger k smooths and can raise bias. Ties and duplicate rows move the vote. It does not extrapolate past the nearest training neighbourhood.

Neural nets, concepts only

A sigmoid squashes a unit into (0, 1). ReLU is max(0, z) and is the usual hidden-unit default. Dropout randomly ignores units while training and is a regulariser, not a way to drop features at scoring time. Vanishing gradients: a deep stack of sigmoids can shrink updates until early layers barely move. Skip connections, ReLU and sensible initialisation are the usual answers. No library boilerplate here. The timed screen is pandas, NumPy and scikit-learn.

Bagging and boosting

Bagging fits trees on bootstrap samples and averages them. A random forest also limits the columns each split may see. That mainly cuts variance. Boosting fits the next model to the previous residual, or more generally to the negative gradient of the loss. Squared error makes that gradient the residual. More trees in a forest usually plateau. More boosting rounds can keep fitting noise if the learning rate or depth is high.

Tree vs linear

Ordinary unregularized least squares does not mathematically require standardization. Scaling can help numerical conditioning and makes coefficient comparisons meaningful. Scale for penalized linear and logistic models, distance-based models, PCA and SVM. Trees generally do not require scaling. A random forest averages trees. Classification aggregates votes or probabilities. Gradient boosting fits successive negative loss gradients, which equal residuals for squared-error regression. A tree predicts a leaf constant outside the range it saw. Fit preprocessing only inside the training fold.

Overfitting signs

Train score far above the validation score. A deep tree, tiny leaves, or a target encoding of a high-cardinality column with no smoothing. A feature that would not exist at the time of the decision, added because the offline number went up. The cure is a holdout you did not tune on, a simpler model, or more data — not another look at the test set.

Cross-validation

k-fold averages k cuts. StratifiedKFold keeps the class rate in each fold. Shuffle only when the rows are exchangeable. Do not shuffle a time series; train on the past and test on the next window. The score you tuned on is optimistic. Quote a holdout that the search never saw.

When to scale

Ordinary unregularized least squares does not mathematically require standardization. Scaling can help numerical conditioning and makes coefficient comparisons meaningful. Scale for penalized linear and logistic models, distance-based models (k-NN, k-means), PCA and SVM. Trees generally do not require scaling. A random forest averages trees. Gradient boosting fits successive negative loss gradients, which equal residuals for squared-error regression. Fit preprocessing only within the training fold. A Pipeline does that per fold.

Leakage rules

Fit the imputer, scaler, encoder, and any target mean on the training rows only. Transform the test with those fitted objects. A feature from after the decision (a later refund, a window that includes the future) will not exist when you score. A column that is a copy of the label, or a deterministic function of it, looks perfect offline and is useless live. A random row split does not fix a feature that already contains the label. For dated rows, split by time. A statistic computed on the whole table (a global target mean, a percentile fit on train+test) leaks the test into the train. For validation or test rows, use training-only target means and a train-global fallback. For training rows, use out-of-fold target encoding. A row's own label must not enter its encoding. Refit encoders inside each outer training fold. Smoothing alone does not remove target leakage.

Test-day tactics

Read the contract

Read the required contract: file names and paths or the function signature, columns and their order, the index policy, types, row ordering and ties, rounding, and any metric threshold. Some data tasks require CSV files, not a returned DataFrame. Inspect examples and tests if they are exposed. Do not assume hidden tests are visible. Run cells in order and verify the final output exists. Trainer shortcuts and auto-imports are not guaranteed on the real platform.

Notebook and imports

Write import pandas as pd and import numpy as np yourself. This trainer preloads them. The real platform may not. If a function's age matters, print pd.__version__ and sklearn.__version__. Use the paths the prompt gives. Look at the file names before you read them. Run the notebook from the top. A name left over from an earlier cell is stale state, not a result. After to_csv, read the file back. Check the columns, their order, the row count and the index. Do not install packages in a proctored test unless that test's rules explicitly allow it. Save and submit the way the platform asks. A variable on the screen is not yet an artifact.

Print the frame

Before a join: print(df.head()), df.shape, df.dtypes, list(df.columns). Print the row count before and after a merge. A sudden multiplication means a duplicated key.

Edges

Empty frame, a column that is all missing, a tie, a duplicated key, a category that appears only on the test side, and a divide by zero. A one-row group makes a sample z-score NaN, because pandas std uses ddof=1.

Rounding

Follow the prompt's rounding and tolerance. Some candidate reports used three decimal places. Do not assume ±0.001. Keep full precision during calculations and round only the requested output. np.std defaults to ddof=0. pandas Series.std and DataFrame.std default to ddof=1.

Time box

A suggested 90-minute budget: 15 minutes probability, 15 minutes ML theory, 20 minutes collection, 15 minutes preprocessing, 20 minutes modeling, 5 minutes final checks. Move on when stuck, and adjust to the actual task weights. This is a suggestion, not an official timing rule. First produce a valid end-to-end baseline and the exact required artifact, then improve it. Do not assume unfinished code, a split alone, or an unexported model earns credit. Check what the platform has saved or submitted.

JOIN, GROUP BY, HAVING

-- WHERE filters rows before the groups. HAVING filters groups.
-- COUNT(*) counts rows; SUM ignores nulls.
SELECT c.segment,
       ROUND(SUM(o.amount), 2) AS revenue,
       COUNT(*) AS orders
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.status = 'paid'
GROUP BY c.segment
HAVING COUNT(*) >= 2
ORDER BY c.segment;

Window functions

-- ROW_NUMBER never ties. RANK skips after a tie. DENSE_RANK does not skip.
-- LAG / LEAD are null at the edge. Filter a window in an outer query, not in WHERE.
-- ROWS is the frame you want for a running sum; RANGE also pulls in peer rows.
SELECT category, sku, revenue,
       ROW_NUMBER() OVER (
         PARTITION BY category
         ORDER BY revenue DESC, sku
       ) AS rn,
       RANK() OVER (
         PARTITION BY category
         ORDER BY revenue DESC
       ) AS rnk,
       DENSE_RANK() OVER (
         PARTITION BY category
         ORDER BY revenue DESC
       ) AS dr,
       LAG(revenue) OVER (
         PARTITION BY category ORDER BY month
       ) AS prev,
       LEAD(revenue) OVER (
         PARTITION BY category ORDER BY month
       ) AS nxt,
       SUM(revenue) OVER (
         PARTITION BY category ORDER BY month
         ROWS BETWEEN UNBOUNDED PRECEDING
                      AND CURRENT ROW
       ) AS running
FROM sales
ORDER BY category, month;

CTEs and CASE

WITH paid AS (
  SELECT customer_id, amount,
         CASE WHEN amount >= 50 THEN 'big' ELSE 'small' END AS band
  FROM orders
  WHERE status = 'paid'
)
SELECT band, COUNT(*) AS n, SUM(amount) AS revenue
FROM paid
GROUP BY band
ORDER BY band;

NULL and LEFT JOIN

-- col = NULL is never true. Use IS NULL. NULL = NULL is not true.
-- A predicate on the right table in WHERE drops the unmatched left rows.
-- Put that predicate in ON. COUNT(col) skips nulls; COUNT(*) does not.
SELECT c.id,
       COALESCE(SUM(o.amount), 0) AS revenue,
       COUNT(o.id) AS paid_orders
FROM customers c
LEFT JOIN orders o
  ON o.customer_id = c.id AND o.status = 'paid'
GROUP BY c.id
ORDER BY c.id;

Later interviews · senior cases

Not the timed screen

Study material for a later conversation, not a question known to be on the timed screen. The invitation is what says whether a case round exists. Do not treat these notes as approved exam material.

Forecasting

Name the decision and the grain first. The baseline is a seasonal naive. Score WAPE and bias, not MAPE alone. Stockouts censor demand. Validate with a rolling origin. Intermittent demand: a rate and a size, then a stock quantile.

Churn

The decision is who to contact under a budget. Risk is not uplift. Split by time. Value times save rate, minus cost. Compare with calling the riskiest customers. Randomise before you trust a save rate.

Price and markdowns

Name the decision variable and the constraints before the model. The objective is usually contribution. Sell-outs do not trace the demand curve. Pilot inside the move you are willing to keep. Markdowns are a small discrete set plus a salvage value.

System design

A weekly list can be a batch. Use one feature query for training and for serving. On failure, republish the last good scores. Log features, version, score, decision, and outcome. A timeout falls back to rules. Shadow, then a slice, with a kill switch.
