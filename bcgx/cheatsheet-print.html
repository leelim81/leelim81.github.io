BCG X data science cheat sheet

Syntax recall for a 90-minute Python test (pandas, NumPy, scikit-learn), plus the SQL practice. Snippets assume import numpy as np and import pandas as pd. pandas Series.std() is the sample standard deviation (ddof=1). NumPy's default is the population one (ddof=0). Leakage rules

Fit the imputer, scaler, encoder, and any target mean on the training rows only. Transform the test with those fitted objects. A feature from after the decision (a later refund, a window that includes the future) will not exist when you score. A column that is a copy of the label, or a deterministic function of it, looks perfect offline and is useless live. A random row split does not fix a feature that already contains the label. For dated rows, split by time. A statistic computed on the whole table (a global target mean, a percentile fit on train+test) leaks the test into the train.

Formulas

# Bayes P(A|B) = P(B|A)P(A)/P(B). PPV = TP/(TP+FP) is that, with A = "truly positive".
# Var = E[X^2] - (E[X])^2. SE = sigma/sqrt(n). A 95% margin is about 1.96*SE.

Correlation and causation

Correlation is a symmetric association. It does not pick a direction. A cause needs a reason: randomisation, a discontinuity, or an assumption you can defend. Conditioning on a mediator (a variable on the path from the cause to the effect) removes part of the effect you wanted. Conditioning on a common effect can create a fake association. A control that is only a common cause is the one you want.

ML theory

Bias and variance

High bias: train and test are both weak. The model is too rigid for the pattern. High variance: train is strong and test is weak. The model memorised the sample. More data mainly cuts variance. A richer model cuts bias. Regularisation, fewer features, and a shallower tree cut variance.

L1 and L2

L2 (Ridge) shrinks coefficients toward 0 and keeps all of them. Correlated features share the weight. L1 (Lasso) can set coefficients to exactly 0, so the feature list gets shorter. Of two correlated features it tends to keep one. The penalty is on the size of the coefficient, so scale the features first or a large-unit column eats the whole penalty.

Which metric

Equal cost, balanced classes: accuracy or F1. Rare positives and a review budget: precision at the top k, or recall at a fixed precision. Accuracy hides a majority classifier. A ranking score: ROC-AUC, or PR-AUC when positives are rare. Gini = 2*AUC - 1. Regression: MAE when outliers should not dominate, RMSE when large misses are expensive, R² against predicting the mean. MAPE explodes when an actual is 0. WAPE = sum(|error|) / sum(|actual|) stays defined while the denominator is not 0.

Precision and recall

Precision = TP / (TP + FP): of the rows you flagged, how many were real. Recall = TP / (TP + FN): of the real positives, how many you flagged. Raising the threshold usually lifts precision and cuts recall. You pick the point from the cost, not from 0.5. class_weight='balanced' (or a threshold that is not 0.5) when the rare class is the one that matters.

ROC and PR

ROC plots the true positive rate against the false positive rate. A sea of true negatives makes the false positive rate look small. Precision-recall plots precision against recall and ignores the true negatives. Use it when positives are rare. AUC summarises the ranking. It is not the operating point you will ship; the threshold chooses that.

Tree vs linear

Linear: readable coefficients, wants scaled numeric inputs, misses interactions unless you add them. A tree cuts thresholds and interactions on its own, ignores monotone rescaling, and predicts a leaf constant outside the training range. A forest averages unstable trees. Boosting fits residuals and overfits if the trees are deep or there are too many of them.

Overfitting signs

Train score far above the validation score. A deep tree, tiny leaves, or a target encoding of a high-cardinality column with no smoothing. A feature that would not exist at the time of the decision, added because the offline number went up. The cure is a holdout you did not tune on, a simpler model, or more data — not another look at the test set.

Cross-validation

k-fold averages k cuts. StratifiedKFold keeps the class rate in each fold. Shuffle only when the rows are exchangeable. Do not shuffle a time series; train on the past and test on the next window. The score you tuned on is optimistic. Quote a holdout that the search never saw.

When to scale

Scale for linear and logistic regression, ridge and lasso, k-means, k-NN, PCA, and SVM. Trees, random forests, and gradient boosting do not need scaled inputs. Fit the scaler on the training fold only. A Pipeline does that per fold.

SQL

JOIN, GROUP BY, HAVING

-- WHERE filters rows before the groups. HAVING filters groups.
-- COUNT(*) counts rows; SUM ignores nulls.
SELECT c.segment,
       ROUND(SUM(o.amount), 2) AS revenue,
       COUNT(*) AS orders
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.status = 'paid'
GROUP BY c.segment
HAVING COUNT(*) >= 2
ORDER BY c.segment;

Window functions

-- ROW_NUMBER never ties. RANK skips after a tie. DENSE_RANK does not skip.
-- LAG / LEAD are null at the edge. Filter a window in an outer query, not in WHERE.
-- ROWS is the frame you want for a running sum; RANGE also pulls in peer rows.
SELECT category, sku, revenue,
       ROW_NUMBER() OVER (
         PARTITION BY category
         ORDER BY revenue DESC, sku
       ) AS rn,
       RANK() OVER (
         PARTITION BY category
         ORDER BY revenue DESC
       ) AS rnk,
       DENSE_RANK() OVER (
         PARTITION BY category
         ORDER BY revenue DESC
       ) AS dr,
       LAG(revenue) OVER (
         PARTITION BY category ORDER BY month
       ) AS prev,
       LEAD(revenue) OVER (
         PARTITION BY category ORDER BY month
       ) AS nxt,
       SUM(revenue) OVER (
         PARTITION BY category ORDER BY month
         ROWS BETWEEN UNBOUNDED PRECEDING
                      AND CURRENT ROW
       ) AS running
FROM sales
ORDER BY category, month;

CTEs and CASE

WITH paid AS (
  SELECT customer_id, amount,
         CASE WHEN amount >= 50 THEN 'big' ELSE 'small' END AS band
  FROM orders
  WHERE status = 'paid'
)
SELECT band, COUNT(*) AS n, SUM(amount) AS revenue
FROM paid
GROUP BY band
ORDER BY band;

NULL and LEFT JOIN

-- col = NULL is never true. Use IS NULL. NULL = NULL is not true.
-- A predicate on the right table in WHERE drops the unmatched left rows.
-- Put that predicate in ON. COUNT(col) skips nulls; COUNT(*) does not.
SELECT c.id,
       COALESCE(SUM(o.amount), 0) AS revenue,
       COUNT(o.id) AS paid_orders
FROM customers c
LEFT JOIN orders o
  ON o.customer_id = c.id AND o.status = 'paid'
GROUP BY c.id
ORDER BY c.id;

Dates

SELECT strftime('%Y-%m', ordered_on) AS ym,
       date(ordered_on, 'start of month') AS month_start,
       date(ordered_on, '+1 month') AS next_month
FROM orders
ORDER BY ordered_on;

Test-day tactics

Read the tests first

The visible example is the contract: column names, order, types, and what a tie should do. Hidden tests follow that contract. Write the function signature the tests call, then make the example pass.

Print the frame

Before a join: print(df.head()), df.shape, df.dtypes, list(df.columns). Print the row count before and after a merge. A sudden multiplication means a duplicated key.

Edges

Empty frame, a column that is all missing, a tie, a duplicated key, a category that appears only on the test side, and a divide by zero. A one-row group makes a sample z-score NaN, because pandas std uses ddof=1.

Rounding

Round the number you return, not the inputs along the way. Numeric answers are three decimals, accepted within 0.001. np.std is population (ddof=0). Series.std() and DataFrame.std() are sample (ddof=1).

Time box

About 4 minutes for a numeric, 3 minutes for a multiple-choice item, 15 minutes for each coding task. A running partial that you can submit beats a blank cell. If a model is not there, ship the split and the metric.

Senior cases

Forecasting

Name the decision and the grain first. The baseline is a seasonal naive. Score WAPE and bias, not MAPE alone. Stockouts censor demand. Validate with a rolling origin. Intermittent demand: a rate and a size, then a stock quantile.

Churn

The decision is who to contact under a budget. Risk is not uplift. Split by time. Value times save rate, minus cost. Compare with calling the riskiest customers. Randomise before you trust a save rate.

Price and markdowns

Name the decision variable and the constraints before the model. The objective is usually contribution. Sell-outs do not trace the demand curve. Pilot inside the move you are willing to keep. Markdowns are a small discrete set plus a salvage value.

System design

A weekly list can be a batch. Use one feature query for training and for serving. On failure, republish the last good scores. Log features, version, score, decision, and outcome. A timeout falls back to rules. Shadow, then a slice, with a kill switch.
